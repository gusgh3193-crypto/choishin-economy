## 개발팀

**오늘 지시한 일**

- `scripts/generate_sitemap.sh`가 글 `title`을 XML 주석(`<!-- ${title} -->`)과 `slug`를 `<loc>`에
  이스케이프 없이 그대로 삽입한다는 점을 지적하며, 제목/슬러그에 `&`, `<`, `>`, `--` 같은 문자가
  들어가면 `seo/sitemap.xml`이 깨진 XML이 될 수 있는지 재현하고, 실재하면 수정하도록 지시했다
  (어제 발견한 keywords 따옴표 버그와 같은 패턴의 미검증 경로). `posts/`는 건드리지 말고 저장소 밖
  임시 디렉터리에서 테스트할 것을 명시.

**완료한 일 (마스터 재검증 완료)**

- 개발팀이 Python `xml.etree.ElementTree`로 직접 추적·실행 테스트한 결과, 가설을 정교화했다: XML
  주석 안의 `&`/`<`/`>` 자체는 well-formed 위반이 아니지만(comment production 규칙상 금지되는 건
  `--` 시퀀스뿐), `--`가 포함된 제목과 `<loc>`(PCDATA)에 raw로 들어가는 `&`/`<`/`>`가 포함된 슬러그는
  확실히 파싱 실패를 일으킴을 `/tmp/sitemap_bugtest/`(저장소 밖, `posts/` 미접촉)에서 실제로 재현했다
  (제목에 `--` 포함 시 `ParseError: not well-formed`, 슬러그에 `&` 포함 시도 동일하게 재현).
- 수정: `xml_escape()` 함수를 추가해 title(주석용)·slug(`<loc>`용) 모두 이스케이프하고, `--`가
  포함된 제목은 (손실 없이 안전하게 치환할 보편적 규칙이 없다는 이유로) 주석 생성 자체를 건너뛰도록
  했다. 날짜/슬러그 추출, robots.txt 생성 등 기존 로직은 건드리지 않았다.
- **마스터 직접 재검증**: `git diff -- scripts/generate_sitemap.sh`로 변경 범위가 `xml_escape` 함수
  추가 + 주석/`<loc>` 두 곳에 적용 + `--` 스킵 조건, 총 14줄 추가/변경뿐임을 확인했다. 마스터가 직접
  `bash scripts/daily_check.sh`를 실제 저장소에서 실행해 9단계 전부 `[PASS]`, "전체 결과: 모든
  점검을 통과했습니다"(EXIT:0)를 확인했다. `git status --short`·`git diff --stat -- seo/`로 실제
  저장소의 `seo/sitemap.xml` 등 산출물이 수정 전후 바이트 단위로 동일해 회귀가 없음도 확인했다.

**특이사항**

- 마스터가 처음 제시한 가설("주석 속 `&`/`<`/`>`도 위반") 중 일부는 개발팀이 실제 Python XML
  파서로 교차 검증해 "주석 속 특수문자는 사실 위반이 아니다"로 정정했다 — 추정에 의존하지 않고
  직접 실행해 가설 자체를 검증한 점이 유의미하다. 다만 지시 취지(일관된 이스케이프 처리)에 따라
  주석 속 문자도 이스케이프 처리했다. 재작업 지시 없음.
