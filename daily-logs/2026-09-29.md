## 개발팀

**오늘 지시한 일**
- `scripts/daily_check.sh`가 sitemap.xml/JSON-LD는 자동 유효성 검증을 하지만
  `seo/robots.txt`는 한 번도 검증하지 않고 있음을 발견. [6/6] 단계로 robots.txt가 (1) 비어있지
  않고 (2) `User-agent:` 줄을 포함하고 (3) `Sitemap:` 줄을 포함하며 (4) 그 URL이
  `/sitemap.xml`로 끝나는지 검증하는 로직을 기존 [4/5], [5/5] 블록과 동일한 스타일로 추가하도록
  지시. `validate_posts.sh`/`generate_sitemap.sh`/`generate_jsonld.sh` 세 스크립트는 절대
  수정하지 말도록 범위를 한정.

**완료한 일 (마스터 재검증 완료)**
- `scripts/daily_check.sh`(189줄)를 마스터가 직접 Read/`git diff`로 재확인. `[1/5]~[5/5]`가
  `[1/6]~[6/6]`로 재번호되고, `[6/6]`에 `ROBOTS_FILE` 변수와 4가지 조건(비어있음/User-agent 줄/
  Sitemap 줄/URL이 `/sitemap.xml`로 끝나는지)을 `robots_errors` 배열에 누적해 `[PASS]`/`[FAIL]`을
  출력하고 `overall_status`·최종 요약 표에 반영하는 로직이 추가됨을 확인. 기존 세 스크립트 파일은
  `git status` 기준 전혀 변경되지 않음(daily_check.sh 1개 파일, 64줄 변경만 존재).
- 개발팀은 이번에도 실행 도구가 없어 "실행 검증은 못 함"이라고 정직하게 보고함(CLAUDE.md 규칙
  준수).
- **마스터가 직접 실행**: `bash scripts/daily_check.sh` 전체를 실행해 `[1/6]~[6/6]` 모두 성공,
  `EXIT_CODE:0` 확인. 이어서 `seo/robots.txt`를 `Sitemap:` 줄이 없는 상태로 고의로 깨뜨린 뒤
  재실행했으나, 예상대로 `[2/6]`(`generate_sitemap.sh`)이 검증 직전에 robots.txt를 항상
  재생성해 실패를 파이프라인 안에서 직접 재현하지는 못했다(원본은 즉시 백업본으로 복구,
  `git diff --stat seo/robots.txt` 기준 변경 없음 확인). 대신 [6/6] 검증 블록 코드만 별도로
  추출해 4가지 실패 케이스(Sitemap 줄 없음 / 빈 파일 / URL이 `.xml`로 안 끝남 / 정상 파일)에
  대해 직접 `source`로 실행한 결과, 각각 정확한 `[FAIL]` 사유와 `exit:1`, 정상 케이스는
  `[PASS]`와 `exit:0`이 출력됨을 확인해 검증 로직 자체의 정확성을 별도로 재현·검증했다.

  실행해 재검증해야 한다. 재작업 지시는 없었음.
