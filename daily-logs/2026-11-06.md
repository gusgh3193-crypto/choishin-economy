## 개발팀

**오늘 지시한 일**

`scripts/validate_posts.sh`의 "1) 파일명 형식 검사"(FILENAME_REGEX로 파일명이

검사"와는 별개인데, 3-2는 `test_date_filename_mismatch.sh`가 전용으로 검증하지만 1번 검사
자체를 전용으로 검증하는 회귀 테스트는 없었다(2026-10-31/11-04/11-05에 반복된 것과 같은
유형의 공백). 이 공백을 메우는 `scripts/test_filename_format.sh`를 신설하고
`scripts/daily_check.sh`에 25번째 단계로 등록하도록 지시했다. 기존 1~24단계 로직·번호는
건드리지 말 것, `validate_posts.sh`의 검사 로직 자체도 수정하지 말 것, git add/commit/push는
마스터가 처리할 것을 명시했다.

**완료한 일 (마스터 재검증 완료)**

- 개발팀이 `scripts/test_filename_format.sh`를 신설(기존 `test_date_filename_mismatch.sh`
  등과 동일한 "임시 디렉터리에 validate_posts.sh 사본 + 임시 posts/" 패턴)했다고 보고. 정상
  형식(`2026-11-06-test-slug.md`) PASS, 날짜 자릿수/구분자 구조가 깨진 경우(`20261106-...`,
  `2026-1-6-...`) FAIL, 슬러그 없음(`2026-11-06-.md`) FAIL을 검증했고, 지시서 예시
  "2026-13-45-...(13월/45일)"는 실제로는 PASS됨(FILENAME_REGEX가 자릿수/구분자 구조만
  보고 달력상 유효성은 검사하지 않음)을 직접 재현 확인해 테스트 케이스를 구조가 실제로
  깨진 경우로 바꿔 작성했다고 보고. 확장자가 `.md`가 아닌 경우는 `post_files=(...*.md)`
  글롭 단계에서 이미 걸러져 FAIL 메시지가 뜨지 않고 "검사할 .md 파일이 없습니다" 경고와
  exit 0으로 끝나는 현재 동작을 정보성으로 기록(FAIL 집계 제외)하고, 이를 "확장자 불일치를
  잡는 전용 검사가 없다"는 별도 공백으로 보고했다. `scripts/daily_check.sh`에 25번째 단계로
  등록(상단 주석 25번 설명 추가, `FILENAME_FORMAT_TEST_SCRIPT` 변수 추가, `[25/25]` 호출
  블록 추가, `[N/24]`→`[N/25]` 표기 일괄 변경, 최종 판정·요약 출력에 25번 항목 추가)했다고
  보고. 단독 실행(exit 0), `bash -n`(SYNTAX_OK), 전체 실행(25단계 모두 성공, exit 0),
  `git status --porcelain`(`scripts/daily_check.sh` 수정, `scripts/test_filename_format.sh`
  신설만, posts/ 변경 없음, `scripts/validate_posts.sh` 변경 없음)을 모두 직접 실행해
  확인했다고 보고.
- **마스터 재검증**: `scripts/test_filename_format.sh`를 마스터가 직접 다시 실행해 4개
  케이스 모두 보고와 동일하게 PASS/FAIL, exit code 0임을 확인했다. `bash -n
