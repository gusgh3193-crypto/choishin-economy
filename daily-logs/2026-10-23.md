## 개발팀

**오늘 지시한 일**

`scripts/validate_posts.sh`가 frontmatter 필수 필드·면책 문구·img alt는 검사하지만 title/
meta_description의 "길이"(검색결과 스니펫에서 잘리는 기준: title 약 60자, meta_description
약 160자)는 검사하지 않는 공백을 확인해, 이를 추가하도록 지시했다. 기존 테스트 스크립트 패턴을
따라 회귀 테스트를 추가하고 `scripts/daily_check.sh`에 16번째 검사로 등록하며, 실제 실행 결과를
확인하도록 지시했다.

**완료한 일 (마스터 재검증 완료)**

- 개발팀이 조사 중 meta_description 길이 검사가 이미 `[WARN]`(절대 FAIL 처리하지 않음) 형태로
  존재했음을 발견해, 지시("초과하면 FAIL")에 따라 title까지 포함한 FAIL 레벨 검사로 교체했다고
  투명하게 보고(기존 동작 변경 사실을 숨기지 않음). `scripts/test_meta_length.sh`를 신설해
  한글 61자/161자 FAIL, 경계값(60/160자, 기준치와 같음) PASS, 한글 글자 수(바이트 아님) 계산
  검증 4건을 추가하고, `scripts/daily_check.sh`에 16번째 단계로 등록했다고 보고. 현재
  `posts/`의 유일한 글은 title 35자/meta_description 79자로 새 기준을 통과한다고 보고.
- **마스터 직접 재검증**: `git diff scripts/validate_posts.sh`, `git diff scripts/daily_check.sh`로
  변경 내용을 전체 확인했다. `bash scripts/validate_posts.sh` 직접 실행 → `[PASS]`, exit 0.
  `bash scripts/daily_check.sh` 전체 직접 실행 → `[1/16]`~`[16/16]` 전 단계 실행되고 최종
  요약에 "16) title/meta_description 길이 검사 회귀 테스트 (test_meta_length.sh) : 성공"이
  출력되며 "전체 결과: 모든 점검을 통과했습니다"로 종료(exit 0)됨을 확인했다. (최초 1회는 개발팀
  작업이 완전히 저장되기 전 시점과 겹쳐 16번 단계가 누락된 출력을 본 적이 있으나, 재실행하자
  정상적으로 16단계 전부 출력됨을 확인해 작업 완료 이후의 상태로 검증을 마쳤다.)

**특이사항**

- 범위를 벗어난 수정 없음. 다른 검사 로직(`split_keywords_items()` 등)은 건드리지 않았다.
- meta_description 검사를 WARN에서 FAIL로 올린 것은 기존 동작 변경이다. 현재 유일한 글은 새
  기준을 통과하므로 당장 영향은 없으나, 향후 글 작성 시(기획팀/블로그 글 작성 담당) 이 기준을
  인지해야 한다.
