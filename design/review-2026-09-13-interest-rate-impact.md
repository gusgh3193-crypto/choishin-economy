## 1. 제목/소제목(H1~H3) 사용 규칙 — **통과**

실제 글의 헤딩 목록(원문 확인):
- H1 1개: `# 금리 인상이 우리 생활에 미치는 영향 5가지` (9번째 줄)
- H2 6개: `## 1. 대출이자 부담 증가`, `## 2. 예금·적금 이자 상승`, `## 3. 물가 안정 효과 (시차 존재)`,
  `## 4. 부동산 시장 위축`, `## 5. 소비 심리 위축`, `## 정리하며`
- H3 0개

가이드가 요구하는 "H1 1개, H2는 소주제 단위, H3는 섹션이 길어질 때만" 조건을 그대로 충족한다.
각 H2 다음에는 예외 없이 본문 1단락이 바로 이어지며(예: `## 1. 대출이자 부담 증가` 바로 다음 문장
"기준금리가 오르면 은행의 대출금리도 함께 오릅니다."), 소제목만 나열되고 내용이 비는 구간은 없었다.

**관찰 사항(위반 아님)**: 프런트매터 `title`은 `"금리 인상이 우리 생활에 미치는 영향 5가지 (2026년 최신)"`로
`(2026년 최신)`이 붙어 있는 반면, 본문 H1은 이 접미사 없이 `금리 인상이 우리 생활에 미치는 영향 5가지`다.
가이드 1번 항목은 "H1과 title이 사실상 같은 문구"라고 서술했는데 완전히 동일하지는 않다. 다만 이는 SEO용
메타 타이틀에 흔히 쓰는 관행(날짜/최신성 키워드 추가)이고 화면에 노출되는 H1 자체의 구조 규칙과는
무관하므로 디자인 관점에서 수정 제안은 하지 않는다.

## 2. 문단 길이와 줄 간격 — **구조는 통과 / 줄 간격은 확인 못 함**

각 문단의 문장 수를 직접 세어 확인했다.

| 위치 | 문장 수 | 비고 |
|---|---|---|
| 리드 문단(9줄 아래 첫 문단) | 3문장 | "뉴스에서 ... 정리했습니다." |
| 1. 대출이자 부담 증가 | 2문장 | 불릿 2개는 별도 |
| 2. 예금·적금 이자 상승 | 3문장 | "반대로 좋은 소식도 있습니다." 포함 |
| 3. 물가 안정 효과 | 2문장 | |
| 4. 부동산 시장 위축 | 2문장 | |
| 5. 소비 심리 위축 | 2문장 | |
| 정리하며(표 아래 마무리 문단) | 2문장 | |

모든 문단이 가이드 기준인 "2~4문장"을 충족하며, 길이도 대략 100~200자 안팎으로 짧아 300자를 넘는
문단은 없다. 따라서 문단 길이 규칙은 **통과**.

**가이드 인용 오차 — 해소됨(2026-09-23 재확인)**: 이 검토를 처음 작성한 2026-09-14 시점에는 스타일
가이드 2번 항목이 "예금·적금 이자 상승 섹션 2문장 약 140자"라고 서술했으나 실제로는 3문장이었다("반대로
좋은 소식도 있습니다. / 금리가 오르면 은행 예금과 적금 금리도 함께 상승하는 경향이 있습니다. / 여윳돈이
있다면 고금리 특판 예금이나 적금 상품을 활용해 이자 수익을 높일 수 있는 시기입니다."). 결과에는 영향
없음(3문장도 2~4문장 기준을 충족)이었고, 당시 다음 가이드 개정 시 "2문장" → "3문장"으로 정정할 것을
제안했다. **현재 `design/style-guide.md` 2번 항목을 재확인한 결과 이미 "3문장 약 140자"로 수정되어
있어 이 지적은 해소되었다("현재 글 분석" 문단, `design/style-guide.md` 27~28행 참고). 추가 조치 불필요.**

**줄 간격(line-height) 1.7~1.8배**: 이는 렌더링(CSS) 속성이며 마크다운 파일에는 해당 정보가 없고
사이트/CSS가 아직 구현되지 않았다(가이드 문서 서두에도 "아직 실제 사이트 코드가 없는 시점"이라고 명시됨).
따라서 이 부분은 **확인 못 함** — 개발팀이 CSS를 구현하는 시점에 재검토가 필요하다.

## 3. 표(table) 사용 규칙 — **통과**

`## 정리하며` 섹션의 표를 그대로 옮기면:

```
| 항목 | 금리 인상 시 영향 |
|---|---|
| 대출이자 | 상승 (부담 증가) |
| 예금이자 | 상승 (수익 증가) |
| 물가 | 시차를 두고 안정화 |
| 부동산 | 수요 위축, 가격 상승 둔화 |
| 소비 | 위축, 저축 선호 증가 |
```

- 열 개수 2열 → 가이드 기준(2~3열) 충족.
- 각 셀이 "상승 (부담 증가)", "시차를 두고 안정화"처럼 짧은 구 단위이며 완결된 문장형 서술은 없음 → 충족.
- 표 앞에 `## 정리하며` 소제목이 있어 표의 목적(요약)을 안내함 → 충족.
- 표는 비교/요약 목적으로만 쓰였고 서술형 설명을 표에 억지로 욱여넣지 않음 → 충족.

4개 세부 기준을 모두 충족하므로 **통과**.

## 4. 목록(bullet) 사용 규칙 — **해소됨(가이드에 반영 완료, 2026-09-23 재확인)**

`## 1. 대출이자 부담 증가` 섹션의 실제 불릿:

```
- 예시: 3억 원을 변동금리로 빌렸다면, 금리가 0.5%p 오를 때 연간 이자 부담은 약 150만 원 증가합니다.
- 대응 방법: 고정금리 전환, 대출 갈아타기(대환대출) 등을 검토해볼 수 있습니다.
```

이 검토를 처음 작성한 2026-09-14 시점에는 스타일 가이드 4번 항목의 **체크리스트 문구**가 "목록은
항목 3개 이상 병렬 나열일 때만"이라고만 되어 있었다. 그런데 실제 글에서 유일하게 쓰인 목록은 항목이
**2개**뿐이어서, 문자 그대로 적용하면 체크리스트 조건(3개 이상)을 충족하지 못했다.

당시 가이드 문서 4번 항목의 "현재 글 분석" 서술 자체는 이 2개짜리 불릿(`예시:`, `대응 방법:`)을
"병렬적으로 나열 가능한 내용에만 선택적으로 사용됐다"며 유지할 패턴으로 인정하고 있어, **가이드 문서
내부에서 체크리스트 문구(3개 이상)와 본문 설명(2개 허용)이 서로 모순**되는 상태였다. 이 불릿은 "같은
종류의 항목을 3개 이상 나열"하는 목록이 아니라 "예시"와 "대응 방법"이라는 서로 다른 성격의 정보를 각각
한 줄 라벨로 구분한 노트(note) 형식에 가깝다고 판단해, 다음과 같이 체크리스트 문구를 보완할 것을
제안했었다.

> "목록은 (a) 같은 성격의 항목이 3개 이상 병렬 나열될 때, 또는 (b) `예시:`/`대응 방법:`처럼 성격이 다른
> 정보를 라벨로 구분해 2개 내외로 보여줄 때 사용한다."

**현재 `design/style-guide.md` 4번 항목 본문(61~65행)과 요약 체크리스트(161행)를 재확인한 결과
이미 위 제안 그대로 "(a) 3개 이상 병렬 나열" / "(b) 라벨로 구분해 2개 내외"로 반영되어 있어, 체크리스트
문구와 본문 설명 간 모순은 해소되었다. 이 글의 불릿 사용(`예시:`, `대응 방법:`)은 (b) 조건에 정확히
해당하므로 규칙과 실제가 일치한다. 추가 조치 불필요.**

## 5. 강조(볼드 등) 사용 규칙 — **통과**

본문 전체를 확인한 결과 `**`로 감싼 볼드 텍스트는 **0회**였다. 유일한 서식은 마지막 줄의 이탤릭 면책
문구뿐이다.

```
*본 글은 일반적인 경제 정보 제공을 목적으로 하며, 개별 투자·대출 결정에 대한 책임은 본인에게 있습니다.*
```

체크리스트 문구("볼드는 단락당 최소한(핵심 수치·라벨 1개 내외)으로만")는 볼드의 **상한**을 정한
규칙이며 사용을 의무화하지 않으므로, 볼드가 0회인 현재 상태는 "남용"에 해당하지 않아 **통과**로
판정한다.

**참고(새 미흡 사항 아님)**: 가이드 5번 항목은 이미 "`예시:`, `대응 방법:` 라벨이나 `0.5%p`, `약 150만 원`
같은 핵심 수치에 볼드를 선택적으로 적용할 것"을 제안해두었다. 이 제안은 어제 시점에 이미 나온 개선
권고이며 오늘 확인 결과 아직 본문에 반영되지 않은 상태(볼드 0회)임을 재확인했다. 규칙 위반은 아니지만
글 작성 담당이 다음 글부터 참고할 수 있도록 다시 한 번 공유할 것을 권장한다.

## 6. 코드 블록 사용 규칙 — **해당 없음**

`posts/2026-09-13-interest-rate-impact.md` 전체를 확인한 결과 인라인 코드(`` `...` ``)나 펜스 코드
블록(` ``` `)이 전혀 쓰이지 않았다. 가이드 6번 항목은 계산식·공식·정확한 수치 예시(이자 계산 공식,
대출 상환 시뮬레이션 등)에 코드 블록을 쓰도록 규정하는데, 이 글은 그런 예시를 코드 블록이 아닌 일반
문장과 불릿(`예시: 3억 원을 변동금리로 빌렸다면...`)으로 서술하고 있어 규칙이 적용될 대상 자체가
없다. 따라서 **해당 없음**이며 위반이 아니다.

## 7. 모바일 화면 가독성 — **구조는 통과 / CSS 의존 항목은 확인 못 함**

마크다운만으로 확인 가능한 부분:
- 표 열 개수 2열 → 좁은 화면에서 잘릴 위험이 낮은 구조 (3번 규칙과 연동, 통과).
- 짧은 문단(2~3문장) + 명확한 소제목 구조 → 스크롤 피로도를 낮추는 패턴 유지됨 (통과).

CSS/사이트가 없어 확인 불가능한 부분(모두 **확인 못 함**):
- 표에 `overflow-x: auto` 래퍼 적용 여부
- 본문 폰트 크기 16px(1rem) 이상 여부
- 단락 좌우 padding 16px 이상 확보 여부

이 항목들은 개발팀이 실제 레이아웃/CSS를 구현하는 시점에 디자인팀이 다시 검수해야 한다.

## 8. 접근성 고려사항 — **표 구조는 통과 / 나머지는 확인 못 함, 면책 문구는 기존에 식별된 이슈 재확인**

- **표 접근성**: 마크다운 표의 첫 행(`항목`, `금리 인상 시 영향`)이 명확한 헤더 역할을 하므로, HTML로
  렌더링할 때 `<th scope="col">`로 매핑하기에 적합한 구조다. 이 구조적 조건은 **통과**. 다만 실제
  `<th>`/`scope` 속성 적용 여부는 HTML이 아직 없어 **확인 못 함**(개발팀 구현 시점에 확인 필요).
- **명도 대비, 폰트 rem 단위, 링크/강조 색상**: 모두 CSS/색상 값이 필요한 항목이며 현재 사이트가 없어
  **확인 못 함**.
- **면책 문구(이탤릭 단독 사용)**: 실제 글 마지막 줄이 `*...*` 이탤릭 하나로만 강조되어 있음을 재확인했다.
  가이드 8번 항목이 이미 "이탤릭만으로는 저시력 사용자에게 불리할 수 있어 향후 CSS에서 배경색 박스/아이콘
  병행을 검토하라"고 명시해 두었고, 이는 "코드가 만들어질 때 결정할 사안"으로 마크다운 표기는 그대로
  두라고 가이드 스스로 유보했다. 오늘 재확인 결과도 동일한 결론이다 — 마크다운 표기를 바꿀 필요는 없고,
  개발팀이 CSS를 만들 때 이 항목을 다시 확인해야 한다.

| 볼드는 단락당 최소한(핵심 수치·라벨 1개 내외) | 통과 | 볼드 0회, 남용 없음(단, 기존 개선 제안 미반영 상태 유지) |
| 코드 블록은 계산식/공식/정확한 수치 예시에만 사용 | 해당 없음 | 이 글에는 인라인 코드·펜스 코드 블록이 전혀 없어 규칙이 적용될 대상 자체가 없음(위반 아님) |
| 본문 16px 이상, 명도 대비 4.5:1 이상, 표 `<th scope="col">` | 구조 통과 / 나머지 확인 못 함 | 표 헤더 구조는 `<th>` 매핑 적합, 폰트·대비는 CSS 미구현으로 확인 불가 |

**집계**: 7개 체크리스트 항목 중 완전 통과 3개(제목 체계, 목록, 볼드), 구조적 통과이나 CSS 의존 부분이
"확인 못 함"으로 남은 항목 3개(문단/줄간격, 표/모바일, 폰트·대비), 해당 없음 1개(코드 블록 — 이 글에
코드 블록이 없어 판정 대상 아님). (2026-09-23 재확인: 목록 항목은 애초 미흡으로 판정했던 가이드 문구
모순이 style-guide.md에 이미 반영되어 해소되었으므로 통과로 갱신.)

## 종합 의견

이 글은 어제 작성된 스타일 가이드가 애초에 이 글을 분석해 만들어졌기 때문에, 마크다운 구조 차원에서
가이드와 크게 어긋나는 부분은 없었다. 2026-09-14 최초 작성 시점에는 2번(문단 길이)과 4번(목록) 항목에서
가이드 문서 자체의 오탈자·모순(2번: "2문장" 서술 vs 실제 3문장, 4번: 체크리스트 "3개 이상" vs 본문
설명의 2개 허용)을 발견해 다음 가이드 개정 시 반영할 것을 제안했다. **2026-09-23 재확인 결과 두 지적
모두 이미 `design/style-guide.md`에 반영되어 해소된 상태다**(2번 항목은 "3문장 약 140자"로 정정됨,
4번 항목은 본문·요약 체크리스트 모두 "(a) 3개 이상 병렬 나열 또는 (b) 라벨로 구분한 2개 내외" 문구로
보완됨). 따라서 두 항목 모두 별도 조치 없이 통과로 갱신한다. 6번(코드 블록) 항목은 이 글에 코드 블록
자체가 없어 위반 여부를 판정할 대상이 아니므로 "해당 없음"으로 별도 표기했다. 그 외 CSS/사이트 구현이
필요한 항목(줄 간격, 폰트 크기, 명도 대비, 표 스크롤 래퍼, `<th>` 속성)은 아직 사이트가 없어 이번
점검에서는 "확인 못 함"으로 남겨두었고, 개발팀이 실제 레이아웃을 구현하는 시점에 디자인팀이 재검수해야
한다.
