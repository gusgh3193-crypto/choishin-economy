# 최신경제 블로그 글 스타일 가이드 (디자인팀)

이 문서는 아직 실제 사이트 코드가 없는 시점에 작성되었다. 배포 플랫폼과 CSS가 정해지면
개발팀이 이 문서를 기준으로 마크다운 → HTML 렌더링 스타일을 구현한다.

분석 대상: `posts/2026-09-13-interest-rate-impact.md` (현재 저장소에 존재하는 유일한 실제 글).
아래 규칙은 이 글의 실제 구조를 근거로 삼았고, 필요한 경우 개선 제안과 이유를 함께 적었다.

---

## 1. 제목/소제목(H1~H3) 사용 규칙

**현재 글 분석**: H1 1개(`# 금리 인상이 우리 생활에 미치는 영향 5가지`), H2 6개(본문 소주제 5개 + `## 정리하며`),
H3는 한 번도 쓰지 않았다. 각 H2 섹션은 본문이 1~2단락으로 짧아 하위 구분이 필요 없었다.

**규칙**:
- **H1**: 글당 한 번만 사용한다. 프런트매터 `title`과 사실상 같은 문구를 쓴다(현재 글도 동일 패턴).
- **H2**: 본문의 큰 소주제 구분에 사용한다. 현재 글처럼 "숫자 + 명사구" 형식(`1. 대출이자 부담 증가`)을
  유지하면 목차형 글에서 스캔하기 쉽다. 이 톤은 유지한다.
- **H3**: H2 섹션 안에서 하위 항목이 2개 이상이고 각각 설명이 길어질 때만 사용한다. 현재 글처럼
  섹션당 1~2단락 분량이면 H3 없이 H2만으로 충분하다 — 불필요한 H3 남발은 목차를 산만하게 하므로
  지금처럼 "섹션이 짧으면 H3 생략"을 기본 원칙으로 유지할 것을 제안한다.
- 소제목 다음에는 반드시 본문 1단락이 바로 오게 하고, 소제목만 나열하고 내용이 비는 구조는 피한다.

## 2. 문단 길이와 줄 간격

**현재 글 분석**: 본문 단락은 모두 2~4문장, 약 100~200자 내외로 짧다(예: 서두 단락 3문장 약 190자,
"예금·적금 이자 상승" 섹션 3문장 약 140자). 5문장을 넘거나 300자를 넘는 단락은 하나도 없다.
이는 모바일에서 스크롤 부담 없이 읽히는 좋은 패턴이므로 그대로 유지한다.

**규칙**:
- 한 단락은 **2~4문장, 대략 150~250자**를 넘지 않도록 권장한다(현재 글의 평균과 일치).
- 한 문장에서 다루는 개념은 1개로 제한한다. 쉼표로 여러 절을 길게 잇지 않는다.
- 단락 간 줄 간격(line-height)은 본문 기준 **1.7~1.8배**를 권장한다(한글은 영문보다 글자가 조밀해
  가독성을 위해 1.5배 미만은 피한다). 단락과 단락 사이에는 최소 1줄 이상의 여백을 둔다.
- 리드(서두) 단락은 소제목 없이 H1 바로 아래 배치하고, 글 전체 요약 역할을 하게 한다(현재 글의
  구조를 그대로 유지 — 좋은 패턴).

## 3. 표(table) 사용 규칙

**현재 글 분석**: `## 정리하며` 섹션에 표가 하나 있다. 2열(`항목`, `금리 인상 시 영향`) × 5행이며,
각 셀은 "상승 (부담 증가)"처럼 짧은 구(句) 단위로 되어 있다. 문장형 긴 텍스트를 셀에 넣지 않은 점이
모바일 가독성에 유리하다.

**규칙**:
- 표는 **비교/요약** 목적일 때만 쓴다. 서술형 설명은 표 대신 일반 문단이나 목록으로 쓴다.
- 열 개수는 **2~3열**을 넘지 않는 것을 권장한다(현재 글은 2열 — 이상적). 열이 4개 이상 필요하면
  표를 나누거나 목록형으로 재구성하는 것을 우선 검토한다.
- 각 셀 내용은 **한 줄, 짧은 구 단위**로 작성한다(현재 글의 "상승 (부담 증가)" 같은 패턴 유지).
  긴 문장을 셀 안에 넣지 않는다.
- 표 앞에는 표가 무엇을 요약하는지 안내하는 소제목이나 짧은 문장을 둔다(현재 글은 `## 정리하며`
  소제목이 이 역할을 함).

## 4. 목록(bullet) 사용 규칙

**현재 글 분석**: "대출이자 부담 증가" 섹션에서만 불릿 2개를 사용했다(`예시:`, `대응 방법:`). 나머지
섹션은 목록 없이 문단으로만 서술했다. 불릿은 "예시"나 "대응 방법"처럼 병렬적으로 나열 가능한
내용에만 선택적으로 사용됐다.

**규칙**:
- 목록은 (a) 같은 성격의 항목이 **3개 이상 병렬 나열**될 때, 또는 (b) `예시:`/`대응 방법:`처럼
  성격이 다른 정보를 라벨로 구분해 **2개 내외**로 보여줄 때 사용한다. 위 두 경우에 해당하지 않고
  항목이 1~2개뿐인데 서로 병렬적이지도 라벨로 구분되지도 않는다면 굳이 목록으로 쪼개지 말고 문단으로
  자연스럽게 서술한다(현재 글의 `예시:`, `대응 방법:` 불릿은 (b)에 해당하며, 나머지 섹션은 문단 서술을
  따르고 있음 — 유지).
- 불릿 항목은 한 줄~두 줄 이내로 짧게 쓴다.
- 개선 제안: 현재 글의 `예시:`, `대응 방법:`처럼 불릿 앞에 라벨을 붙이는 패턴은 좋으나, 라벨에
  강조(볼드) 처리가 없어 스캔성이 떨어진다. 아래 5번 항목 참고.

## 5. 강조(볼드 등) 사용 규칙

**현재 글 분석**: 본문 전체에 볼드(`**`)가 **단 한 번도 쓰이지 않았다**. 유일한 서식 강조는 글 마지막의
면책 문구에 쓰인 이탤릭(`*...*`) 뿐이다.

**규칙 및 개선 제안**:
- 면책 문구를 이탤릭으로 구분하는 현재 방식은 유지한다(경고성 문구를 시각적으로 분리하는 좋은 패턴).
- **제안(톤 변경 아님, 가독성 보완)**: 불릿 항목의 라벨(`예시:`, `대응 방법:`)이나 핵심 수치
  (`0.5%p`, `약 150만 원`)처럼 독자가 빠르게 찾아야 하는 정보에는 볼드를 선택적으로 적용할 것을
  권장한다. 다만 한 단락에 볼드를 2개 이상 쓰지 않는다 — 과도한 강조는 오히려 가독성을 해치고
  현재 글의 담백한 톤(장식 없는 서술형)과 어긋나므로, "핵심 수치·라벨 1개 정도"로 최소한만 적용한다.
- 볼드를 문장 전체나 소제목 대체 용도로 쓰지 않는다.

## 6. 모바일 화면 가독성

- 표는 열이 2~3개로 적어야 좁은 화면에서 잘리지 않는다(3번 규칙과 연동). 그래도 화면 폭이
  360px 이하로 좁을 경우를 대비해, 개발팀은 표에 `overflow-x: auto`를 적용한 래퍼(wrapper)를 두어
  표가 화면 밖으로 잘리는 대신 가로 스크롤되게 만드는 것을 권장한다. 표 셀 텍스트를 줄바꿈
  강제(`white-space: nowrap`)하지 않도록 하여 좁은 화면에서 셀이 세로로 늘어나도 읽을 수 있게 한다.
- 본문 폰트 크기는 모바일 기준 최소 16px(1rem) 이상을 권장한다. 16px 미만이면 iOS 브라우저에서
  입력창 자동 확대 등 부작용이 있고, 무엇보다 장문의 경제 정보 글을 읽는 독자 피로도가 커진다.
- 단락 좌우 여백(padding)은 모바일에서 최소 16px 이상 확보해 텍스트가 화면 가장자리에 붙지 않게 한다.
- 현재 글처럼 짧은 단락 + 명확한 소제목 구조를 유지하면 모바일 스크롤 피로도가 낮다 — 이 구조를
  기본값으로 유지할 것을 권장한다.

## 7. 접근성 고려사항 (향후 CSS 작성 시 참고)

- **명도 대비(contrast)**: 본문 텍스트와 배경의 명도 대비는 WCAG AA 기준인 **4.5:1 이상**을
  맞춘다. 소제목처럼 큰 글자(18px 이상 bold 또는 24px 이상)는 **3:1 이상**도 허용되나, 본문은
  4.5:1을 기본값으로 한다. 연한 회색 텍스트(예: `#999` 이하)를 흰 배경에 본문용으로 쓰지 않는다.
- **폰트 크기**: 본문 기본 16px 이상, 소제목(H2)은 본문 대비 1.3~1.5배, H1은 1.8~2배 수준을 권장한다.
  사용자가 브라우저 확대(zoom)를 해도 레이아웃이 깨지지 않도록 폰트 크기는 `rem` 단위 사용을 권장한다.
- **표 접근성**: 표를 실제 HTML `<table>`로 렌더링할 때 `<th>`(헤더 셀)를 반드시 사용하고
  `scope="col"` 속성을 넣어 스크린리더가 열 제목을 읽을 수 있게 한다. 현재 글의 표는 첫 행이
  헤더(`항목`, `금리 인상 시 영향`) 역할을 하므로 이 구조를 그대로 `<th>`로 매핑하면 된다.
- **링크/강조 색상**: 볼드나 링크에 색상을 추가로 쓸 경우, 색상만으로 정보를 구분하지 않는다
  (색맹 사용자 고려). 밑줄이나 굵기 같은 비색상 단서를 함께 준다. 특히 링크는
  `design/color-palette.md` 2-4번("색상 외 추가 단서 필요성")에서 이미 정리했듯,
  방문 전/후 색상(`#0B5FA5`/`#6A4C93`) 차이만으로는 색맹 사용자가 구분하기 어려울 수
  있으므로 **밑줄(underline)을 함께 적용할 것을 권장한다**(방문 후 링크는 밑줄을
  점선 등으로 달리하는 것도 보조 수단으로 검토 가능). 구체적 색상값·근거는
  `design/color-palette.md` 참고.
- **줄 간격/자간**: 접근성 가이드라인(WCAG 1.4.8)에서 권장하는 줄 간격 1.5배 이상, 단락 간 간격은
  글자 크기의 2배 이상을 참고한다. 2번 항목의 1.7~1.8배 권장치는 이 기준을 상회해 안전하다.
- **면책 문구 등 보조 정보**: 이탤릭만으로 강조하지 말고(저시력 사용자는 이탤릭이 읽기 어려울 수
  있음), 실제 CSS 구현 시에는 이탤릭 대신 약간의 배경색 박스나 아이콘을 함께 쓰는 것을 검토할 것을
  제안한다. 다만 이는 코드가 만들어질 때 결정할 사안이며 현재 마크다운 표기(`*...*`)는 그대로 둔다.
- 실제 색상 팔레트는 `design/color-palette.md` 참고.

## 요약 체크리스트 (개발팀/글 작성 담당용)

- [ ] H1은 글당 1개, H2는 소주제 단위, H3는 섹션이 길어질 때만
- [ ] 단락은 2~4문장(150~250자) 이내, 줄 간격 1.7~1.8배
- [ ] 표는 2~3열, 셀은 짧은 구 단위, 모바일에서는 가로 스크롤 래퍼 적용
- [ ] 목록은 (a) 같은 성격의 항목이 3개 이상 병렬 나열될 때, 또는 (b) `예시:`/`대응 방법:`처럼 성격이 다른 정보를 라벨로 구분해 2개 내외로 보여줄 때 사용
- [ ] 볼드는 단락당 최소한(핵심 수치·라벨 1개 내외)으로만
- [ ] 본문 16px 이상, 명도 대비 4.5:1 이상, 표는 `<th scope="col">` 사용
- [ ] 링크는 색상뿐 아니라 밑줄 등 비색상 단서 병행 (색맹 사용자 고려, `design/color-palette.md` 2-4번 참고)
