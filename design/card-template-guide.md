# 카드뉴스 기본 템플릿 사용 가이드 (디자인팀)

## 왜 지금 만들었나

`.claude/agents/design-team.md` 업무 3번(카드뉴스 시안)은 "마케팅팀이 작성한 카드뉴스
스크립트를 실제 화면/이미지 시안으로 구현한다"고 되어 있다. 하지만 오늘은 마케팅팀이
호출 대상이 아니고, 실제 카드뉴스 문구(스크립트)도 아직 없다. `design/` 폴더에 카드뉴스
관련 파일이 하나도 없었으므로, 과거에 실제 사이트 코드 없이 `style-guide.md`·
`color-palette.md`를 먼저 만들어둔 것과 같은 방식으로 — 실제 문구가 들어오기 전에
재사용 가능한 **빈 틀(템플릿)** 만 먼저 준비했다. `design/card-template.html`은
배포용이 아니며, 마케팅팀 스크립트가 오면 그 내용으로 플레이스홀더를 교체해서 쓰는
용도다.

## 재사용한 색상 (새로 만든 색 없음)

`design/site.css`에 정의된 CSS 변수를 그대로 가져다 썼다. 전부 `design/color-palette.md`
1번·2-2번에서 이미 대비(contrast)가 검증된 값이다.

| 변수 | 값 | 템플릿에서 쓴 곳 |
|---|---|---|
| `--color-bg` | `#FFFFFF` | 카드 배경 |
| `--color-text` | `#333333` | 본문 요약, 세부 포인트, 푸터 텍스트 |
| `--color-heading` | `#1A1A1A` | 카드 제목(`.card-title`) |
| `--color-link` | `#0B5FA5` | 상단 라벨(`.card-eyebrow`) — 실제 링크가 아니라 색만 재사용 |
| `--color-warning-bg` / `--color-warning-text` | `#FFF3E0` / `#6B3E00` | 면책 문구 자리(`.card-disclaimer`), 미리보기 상단 안내문 |

새 색상 변수나 새 hex 값을 추가하지 않았으므로, `color-palette.md` 2-2번에서 이미
확인된 대비비(본문 12.63:1, 제목 17.41:1, 라벨 6.57:1, 면책 박스 8.28:1 — 모두 기준
4.5:1 이상)가 그대로 적용된다. 별도로 다시 계산하지 않았다.

폰트도 `site.css`와 동일하게 `-apple-system, "Apple SD Gothic Neo", "Malgun Gothic",
sans-serif`를 그대로 썼다.

## 비율/크기 근거

- **정방형 1:1 (1080×1080px)**: 인스타그램, 카카오톡 채널 등에서 가장 흔히 쓰이는
  SNS 카드뉴스 기본 비율.
- **4:5 (1080×1350px)**: 모바일 피드에서 정방형보다 세로로 더 큰 화면 비중을
  차지해 노출에 유리한, 역시 흔히 쓰이는 비율.
- 화면에서는 `aspect-ratio`와 `vw`(뷰포트 너비) 기반 크기(`width: min(90vw, 440px)`)로
  반응형으로 보여주지만, 실제 이미지로 내보낼 때는 위 px 기준(또는 2배 해상도인
  2160×2160 / 2160×2700)으로 캡처/렌더링하면 된다. (2026-10-09 정정: 과거 "vmin 기반"
  표기는 실제 CSS 단위와 달라 vw로 수정함)

## 마케팅팀 스크립트가 오면 교체할 자리

`design/card-template.html` 안의 `[...]` 표시된 자리를 실제 문구로 바꾸면 된다.

| 자리 | 설명 |
|---|---|
| `[시리즈/카테고리 라벨 자리]` | 카드 상단 작은 라벨 (예: "재테크 기초") |
| `[카드뉴스 제목 자리]` | 카드의 메인 타이틀 |
| `[핵심 요약 문구 자리 — 마케팅팀 스크립트로 교체]` | 제목 아래 핵심 요약 1~2문장 |
| `[세부 포인트 1~3 자리]` | 불릿 포인트. 필요 없으면 `<li>` 자체를 삭제 (style-guide.md 4번: 병렬 항목 3개 이상 또는 라벨 2개 내외일 때만 목록 사용 원칙과 동일하게, 포인트가 1~2개뿐이면 목록 대신 요약 문단에 자연스럽게 녹이는 것도 검토) |
| `[투자·대출 등 ... 면책 문구 자리]` | 금전적 판단에 영향을 줄 수 있는 내용일 때만 채운다(CLAUDE.md 콘텐츠 규칙). 해당 없으면 이 블록 전체를 삭제 |
| `[최신경제 워드마크/로고 자리]` | 실제 로고/워드마크가 정해지면 교체 |
| `[1/5]` | 카드뉴스가 여러 장일 때 순번 표시, 1장짜리면 삭제 |

**참고 (2026-10-12 추가)**: `[최신경제 워드마크/로고 자리]`가 실제 로고 이미지(`<img>`)로
교체될 때는 `design/style-guide.md` 8번 접근성 섹션에 신설된 "이미지 대체 텍스트(alt)" 규칙을
따른다(장식용이면 `alt=""` 또는 짧은 브랜드명, 정보를 담은 이미지면 핵심 정보 요약).

## 카드뉴스 폰트 크기 재점검 (2026-10-08)

### 발견된 문제

최초 작성 시(2026-10-07) 색상은 `color-palette.md`에서 검증된 값을 재사용했다고 명시했지만,
**폰트 크기는 점검하지 않았다.** `design/style-guide.md` 7번("본문 폰트 크기는 모바일 기준
최소 16px(1rem) 이상")·8번("본문 기본 16px 이상")은 접근성/가독성 기준으로 16px 이상을
명확히 요구하는데, `design/card-template.html`을 다시 열어 직접 대조한 결과 아래 항목들이
16px 미달이었다(1rem = 16px은 `design/site.css`의 `html { font-size: 100%; }` /
`body { font-size: 1rem; }`로 확인 — 별도 축소 없음).

| 요소 | 당시 값 | px 환산 | 비고 |
|---|---|---|---|
| `.card-disclaimer` | 0.78rem | 12.48px | 과제에서 지적됨 |
| `.card-footer` | 0.8rem | 12.8px | 과제에서 지적됨 |
| `.card-eyebrow` | 0.85rem | 13.6px | 과제에서 지적됨 |
| `.card-slot-label` | 0.9rem | 14.4px | 과제에서 지적됨 |
| `.card-points` | 0.95rem | 15.2px | **재점검 중 추가로 발견** (과제에 언급 안 됐으나 직접 대조 결과 미달) |
| `.preview-note` | 0.95rem | 15.2px | **재점검 중 추가로 발견** (미리보기 페이지 안내문, 카드 바깥 요소) |

`.card-title`(1.6rem=25.6px)과 `.card-summary`(1rem=16px)는 기준을 충족해 변경하지 않았다.

### 판단: style-guide.md 16px 규칙을 그대로 가져올 수 있는가

"느낌"이 아니라 아래 근거로 판단했다.

1. **16px 규칙의 원래 근거가 카드뉴스에는 성립하지 않는 부분이 있다.** style-guide.md 7번은
   "16px 미만이면 iOS 브라우저에서 입력창 자동 확대 등 부작용"을 근거로 든다 — 카드뉴스에는
   입력창이 없으므로 이 근거는 적용되지 않는다. 8번은 "사용자가 브라우저 확대(zoom)를 해도
   레이아웃이 깨지지 않도록"(WCAG 1.4.4 reflow 전제)을 근거로 든다 — 하지만 카드뉴스는 완성 후
   **PNG/JPG 같은 플랫 래스터 이미지로 내보내져 인스타그램/카카오 등에 게시**되므로, 게시된
   최종 결과물에는 DOM이나 reflow 자체가 없다. 사용자가 그 이미지를 확대해도 "레이아웃이
   깨진다/안 깨진다"는 개념이 적용될 여지가 없고(사진처럼 통째로 확대될 뿐), 스크린리더도 이미지
   속 텍스트를 읽지 못하므로 폰트 크기와 무관하게 접근성 한계가 이미 존재한다. 즉 16px 규칙이
   깔고 있는 "reflow 가능한 라이브 웹페이지"라는 전제가 카드뉴스 최종 결과물에는 들어맞지 않는다.
2. **실제 내보내기 시 글자의 최종 픽셀 크기는 rem 값만으로 정해지지 않는다.** 코드를 보면
   `.card { width: min(90vw, 440px); ... }`로 화면 미리보기 카드는 **최대 440px**로 캡핑돼
   있다. 그런데 가이드는 "실제 이미지로 내보낼 때는 이 비율을 유지한 채 1080px 기준(또는 2x인
   2160px)으로 캡처/렌더링"하라고 안내한다 — 440px 카드를 1080px 캔버스에 그대로 넣으면 안쪽에
   여백만 남고 채워지지 않으므로, 내보내기 과정은 반드시 약 2.45배(1080/440) 확대를 거쳐야
   한다. 이 확대가 적용되면 0.78rem(12.48px)도 최종 이미지에서는 대략 30px 안팎으로 커진다.
   **다만 이 확대 비율은 파일 어디에도 고정돼 있지 않고, 실제로 어떤 도구/방법으로 내보낼지
   아직 정해지지 않았다** — 즉 "확대되니 작아도 된다"는 가정에만 의존하는 것은 위험하다
   (도구가 바뀌거나 440px 캡 값이 수정되면 확대 비율도 조용히 달라져 최종 텍스트 크기가
   작아질 수 있음).
3. **면책 문구는 본문보다 작아서는 안 된다.** `.card-disclaimer`는 CLAUDE.md 콘텐츠 규칙상
   투자·대출 등 금전적 판단에 영향을 줄 수 있는 경고성 정보다. 경고/법적 고지 성격의 텍스트를
   본문(`.card-summary`, 1rem)보다 작게 만드는 것은 일반적인 공지 설계 상식에도 맞지 않는다.
4. **캔버스 여유가 충분하다.** 1080px은 모바일 화면 폭(360~430px)보다 훨씬 큰 캔버스이므로,
   본문급 텍스트를 16px로 올려도 레이아웃이 깨지거나 공간이 부족해질 위험이 낮다.

**결론**: 카드뉴스는 고정 캔버스로 내보내지는 이미지라는 점에서 style-guide.md 16px 규칙의
*근거*(브라우저 reflow, iOS 입력창 자동 확대)가 그대로 적용되지는 않는, 블로그 본문과는 다른
매체다. 그래서 숫자를 블로그 규칙에서 그대로 복사해 온 것이 아니라, 위 1~4번처럼 카드뉴스 자체의
근거로 별도로 판단했다. 다만 판단 결과 도출된 **카드뉴스용 최소 기준도 동일하게 1rem(16px)**로
정했다 — 확대 비율에 의존하는 가정이 불확실하고, 면책 문구를 본문보다 작게 둘 이유가 없으며,
캔버스 여유가 충분해 16px로 올려도 비용이 없기 때문이다. 즉 "카드뉴스니까 확인 안 해도 된다"가
아니라, 카드뉴스에 맞는 기준을 다시 세운 결과 블로그와 같은 수치에 도달했다는 의미다.

### 새 기준 (카드뉴스용, 명시)

- **authored CSS 기준(화면 미리보기 440px 카드 기준) 모든 텍스트는 최소 1rem(16px) 이상.**
  제목류(`.card-title`)처럼 위계상 더 커야 하는 요소는 그 이상으로 유지한다.
- 크기로 위계를 더 못 줄이게 된 요소(`.card-eyebrow` 등)는 **font-weight·색상**으로 위계를
  구분한다(`color-palette.md` 1번의 H1/H2가 크기 대신 색상 통일 + 크기로만 구분하는 것과 반대
  방향이지만 같은 원리 — 크기 외 수단으로 위계를 표현).
- 이 기준은 "화면 미리보기(440px 카드)" 시점의 authored 값 기준이며, 실제 1080px 내보내기 시의
  확대 비율은 검증되지 않았으므로 앞으로 내보내기 도구/방법이 정해지면 **실제 내보낸 이미지에서
  글자가 깨지거나 흐려지지 않는지 별도로 다시 확인**해야 한다(아래 "확인 못 한 부분" 참고).

## 카드뉴스 미리보기 갤러리 페이지의 제목 태그 규칙 (2026-10-11)

### 발견된 문제

`design/card-template.html`을 다시 열어 대조한 결과, 같은 HTML 문서 안에 `<h1 class="card-title">`가
두 번 쓰여 있었다(1:1 카드 슬롯과 4:5 카드 슬롯 각각). 한 문서에 `<h1>`이 여러 개 있으면 스크린리더·
SEO 입장에서 "페이지의 주된 제목이 무엇인지" 혼란을 줄 수 있다는 지적이 있었다.

### 1차 판단 — `design/cs-handoff-guide.md` 1번 절차 적용

`design/cs-handoff-guide.md` 1번 "1단계: 신고 내용을 기존 기준 문서와 대조한다" 절차를 그대로
적용했다.

- **대조한 기준**: `design/style-guide.md` 1번 "H1: 글당 한 번만 사용한다"가 이 저장소에서 h1
  개수에 대해 유일하게 명시된 규칙이다.
- **그 규칙의 실제 범위 확인**: style-guide.md 1번 규칙은 독립된 일반 원칙이 아니라, 문서 맨 위
  "분석 대상: `posts/2026-09-13-interest-rate-impact.md`"라고 명시한 대로 **블로그 글(`posts/`)의
  마크다운 → HTML 렌더링**을 분석해 만든 규칙이다("H1은 글당 한 번만 사용한다"의 "글"은 `posts/`의
  블로그 포스트를 가리킨다). `card-template.html`은 `posts/`의 글이 아니라 "카드뉴스 미리보기
  갤러리 페이지"이며, 이 사실은 파일 1~8번째 줄 주석에도 명시돼 있다("배포용이 아니라... 재사용
  가능한 템플릿", "실제 발행/배포하지 않습니다").
- **cs-handoff-guide.md 1번 2단계 분류**: "확인된 이슈"는 "신고 내용이 기준 문서의 구체적
  수치/규칙을 실제로 위반하는 경우"로 정의된다. style-guide.md 1번 규칙이 명시적으로 `posts/`
  블로그 글을 대상으로 쓰여진 것이므로, 블로그 글이 아닌 카드뉴스 미리보기 페이지에 그 문구를
  문자 그대로 적용해 "위반"이라 단정할 수는 없다. 동시에 cs-handoff-guide.md 1번 2단계 주석에
  명시된 대로, "단순 의견"도 아니다 — h1 중복이 스크린리더·SEO에 혼란을 줄 수 있다는 지적은
  근거(시맨틱 HTML 원칙)가 있는 지적이며 취향 문제가 아니다.
- **결론**: cs-handoff-guide.md 1번 "주의" 항목이 말하는 **"기준 문서에 아예 정의되지 않은 새
  영역"**에 해당한다. style-guide.md·card-template-guide.md 어디에도 "카드뉴스 미리보기 갤러리
  페이지(한 문서에 서로 다른 카드 슬롯 여러 개를 나란히 보여주는 페이지)의 제목 태그를 어떻게
  쓸지"에 대한 규칙이 없었다. 따라서 **"기준 미비"**로 분류한다.

### 새 규칙 (카드뉴스 미리보기 갤러리 페이지용, 신설)

- **카드뉴스 미리보기 갤러리 페이지(여러 카드 슬롯을 한 문서에 나란히 보여주는 시안 페이지)에서는
  문서 전체에 `<h1>`을 두지 않는다.** 이 페이지는 "완성된 한 장의 글/카드"가 아니라 "복수의 독립된
  카드 산출물을 나란히 비교해 보는 갤러리"이므로, 문서 전체를 대표하는 단 하나의 주제가 없다 —
  `style-guide.md` 1번 규칙의 "H1 = 글 전체의 주제 하나"라는 전제 자체가 이 페이지 구조와 맞지
  않는다.
- 각 카드 슬롯 안의 제목(`.card-title`)은 `<p class="card-title">`로 쓴다. `<h2>` 등 다른 heading
  태그로 바꾸지 않는 이유는, 이 문서에는 heading 레벨의 기준이 되는 `<h1>`이 없어서 `<h2>`를 쓰면
  "존재하지 않는 h1 아래의 2단계 제목"이라는 잘못된 문서 개요(outline)를 암시하게 되기 때문이다.
  `<p>`는 어떤 heading 레벨도 암시하지 않으면서, 카드 안에서 "이 카드의 제목은 이것"이라는 시각적
  정보만 전달한다.
- `.card-title`의 CSS 규칙(`font-size: 1.6rem`, `line-height: 1.4`, `margin: 0 0 16px`, 색상
  `var(--color-heading)`)은 **클래스 셀렉터이므로 태그를 바꿔도 그대로 적용**된다. 즉 이 변경은
  시각적 결과를 전혀 바꾸지 않는, 태그만 바꾸는 최소 수정이다.
- 실제 카드뉴스를 1장씩 독립 이미지로 내보낸 뒤에는(각 이미지는 PNG/JPG 같은 플랫 래스터 이미지로,
  `card-template-guide.md` 위 "카드뉴스 폰트 크기 재점검" 섹션에서 이미 정리했듯 내보낸 결과물에는
  DOM·heading 개념 자체가 없다) h1 중복 문제가 원천적으로 발생하지 않는다. 이 규칙은 **아직
  개별 이미지로 내보내지기 전, 미리보기/비교용 HTML 문서 자체**의 시맨틱 구조를 다루는 규칙이다.

### 수정 내역 (`design/card-template.html`)

| 위치 | 수정 전 | 수정 후 |
|---|---|---|
| 1:1 카드 슬롯 제목 | `<h1 class="card-title">[카드뉴스 제목 자리]</h1>` | `<p class="card-title">[카드뉴스 제목 자리]</p>` |
| 4:5 카드 슬롯 제목 | `<h1 class="card-title">[카드뉴스 제목 자리]</h1>` | `<p class="card-title">[카드뉴스 제목 자리]</p>` |

`.card-title` 클래스의 CSS 선언(폰트 크기·줄 간격·색상·margin)은 변경하지 않았다.

## 카드뉴스 플레이스홀더별 권장 글자 수 기준 (2026-10-13)

### 배경

마스터가 실제 브라우저로 "카드가 정해진 높이(aspect-ratio 고정 박스)를 넘쳐 글자가 잘리는지"를
확인하려면, 마케팅팀이 실제로 넣을 법한 **현실적인 최대 길이** 문구가 필요하다. 그런데 지금까지
각 플레이스홀더(`[시리즈/카테고리 라벨 자리]`, `[카드뉴스 제목 자리]`, `[핵심 요약 문구 자리]`,
세부 포인트 1~3, `[면책 문구 자리]`)에는 권장 글자 수 기준이 전혀 없었다. 이 섹션은 그 기준을
새로 정한다.

### 1차 판단 — `design/cs-handoff-guide.md` 1번 절차 적용

- **대조한 기준**: `design/style-guide.md`·`design/color-palette.md` 전체를 대조했다. 두 문서에는
  "플레이스홀더/텍스트 요소별 권장 글자 수(자 단위)"를 수치로 정의한 규칙이 없다. 가장 가까운 것은
  style-guide.md 2번 "단락은 2~4문장, 150~250자"(블로그 본문 **단락** 기준)와 4번 "불릿 항목은
  한 줄~두 줄 이내로 짧게"(블로그 **목록** 기준)뿐이며, 둘 다 카드뉴스 전용 수치는 아니다. 이
  문서(card-template-guide.md) 자체에도 폭/비율/색상/폰트 크기 섹션은 있지만 글자 수 기준은
  없었다.
- **cs-handoff-guide.md 1번 "주의" 항목 적용**: "신고 내용이 기준 문서에 아예 정의되지 않은 새
  영역을 지적하는 경우는 '위반'도 '단순 의견'도 아닌 **기준 미비**로 별도 표시한다"는 조건에
  정확히 해당한다. 위반(기존 기준을 못 지킨 것)도 아니고 취향 문제도 아니라, 애초에 기준 자체가
  없었기 때문이다.
- **결론**: **기준 미비**로 분류하고, cs-handoff-guide.md 1번 "주의" 항목대로 "임의로 즉흥
  결정하지 않고, 기존 문서의 근거와 일관되게" 아래 기준을 새로 제정한다.

### 계산 근거 (카드 실제 가로폭 기준)

- **카드 폭**: `design/card-template.html` 69~80번째 줄 `.card { width: min(90vw, 440px);
  padding: 6%; box-sizing: border-box; }`. 미리보기 기준 최대값 **440px**로 계산한다.
- **좌우 가용 폭**: CSS 스펙상 `padding`의 퍼센트 값은 가로·세로 모두 containing block의 "폭"
  기준으로 계산되므로, 440px × 6% = 26.4px(좌우 각각). 좌우 합 52.8px를 빼면 카드 내부 실제
  텍스트 가용 폭은 **440 − 52.8 ≈ 387px**.
- **글자 폭 추정(근사치, 미검증)**: 이 템플릿이 쓰는 한글 산세리프 글꼴(`-apple-system, "Apple SD
  Gothic Neo", "Malgun Gothic"`)은 한글 음절 1자가 대략 font-size와 비슷한 정사각형 폭으로
  렌더링되는 것이 일반적인 근사치다. 이 문서는 아직 실제 브라우저로 글자 폭을 측정하지 못했으므로
  (이 문서 맨 아래 "확인 못 한 부분" 참고), **1자 ≈ 1em**이라는 근사값으로 "1줄 용량(자) = 가용
  폭(px) ÷ 폰트 크기(px)"를 계산했다. 이는 산술 근사치이며, 실제 렌더링 폭과 다를 수 있다 —
  마스터가 오늘 헤드리스 브라우저로 확인할 때 이 근사치보다 적게/많게 들어갈 수 있다는 점을
  전제로 삼아야 한다.
- 요소별 실제 가용 폭(요소 자체에 추가 내부 패딩이 있으면 그만큼 더 차감)과 1줄 용량:
  - `.card-eyebrow`: 16px(1rem), `font-weight: bold`. 볼드체는 보통체보다 통상 5~10% 더 넓게
    렌더링되므로 10% 더 차감. 1줄 용량 ≈ 387 ÷ (16×1.1) ≈ **22자**.
  - `.card-title`: 25.6px(1.6rem), 보통체. 1줄 용량 ≈ 387 ÷ 25.6 ≈ **15자**.
  - `.card-summary`: 16px(1rem), 보통체. 1줄 용량 ≈ 387 ÷ 16 ≈ **24자**.
  - `.card-points` 각 `<li>`: `.card-points { padding-left: 1.1rem; }`(17.6px)만큼 추가 차감 →
    가용 폭 387 − 17.6 ≈ 369.6px. 1줄 용량 ≈ 369.6 ÷ 16 ≈ **23자**.
  - `.card-disclaimer`: 자체 `padding: 10px 12px;`만큼 좌우 24px 추가 차감 → 가용 폭
    387 − 24 ≈ 363.2px. 1줄 용량 ≈ 363.2 ÷ 16 ≈ **22자**.

### 주의 — 이 기준의 성격

- 위 수치는 "1자 ≈ 1em" 근사치와 440px 카드 기준 산술 계산으로 도출한 **권장 가이드라인**이며,
  실제 브라우저 렌더링으로 글자가 넘치는지 자체를 확인한 결과는 **아니다**. 실제 글꼴 렌더링
  (커닝, 자간, 특정 글자의 실제 폭 차이 등)에 따라 이 권장치를 지켜도 여전히 넘칠 수 있고, 반대로

  브라우저 렌더링 확인 못 함" 한계와 동일하다.
- 따라서 이 표의 숫자는 마스터가 오늘 헤드리스 브라우저로 오버플로 여부를 테스트할 때 "현실적인
  최대 길이" 테스트 문구를 만드는 **입력값**으로 쓰기 위한 것이다. 테스트 결과 실제로 넘치는 것이
  확인되면, 이 표의 숫자를 더 낮추는 재조정이 필요하다(디자인팀이 추가로 검토).
- **(2026-10-13 같은 날 갱신) 바로 그 테스트가 실행됐고, 실제로 넘치는 것이 확인됐다(FAIL).**

마스터가 이 환경의 헤드리스 Chromium(Playwright, 뷰포트 1280×900)으로 개발팀이 만든 테스트

#### 역산한 예산(budget)

- 1:1 카드(438px)가 허용하는 "콘텐츠 wrapper" 예산 = 438 − 52.8(padding) − 39(footer) =
  **346.2px**. 지금 510px이 필요하므로 약 164px(32%) 초과.
- 4:5 카드(548px)의 콘텐츠 wrapper 예산 = 548 − 52.8 − 39 = **456.2px**. 지금 510px이
  필요하므로 약 54px(11%) 초과.
- 1:1과 4:5가 `.card-title`·`.card-summary`·`.card-points`·`.card-disclaimer` 등 완전히 같은
  마크업/CSS 구조를 공유한다(`design/card-template.html` 163~209번째 줄, 두 카드 슬롯의 내부
  구조가 동일). 따라서 **둘 다 통과하려면 더 타이트한 1:1 예산(346.2px) 기준으로 공용 글자 수

- 콘텐츠 wrapper(510px) 안에서 비중이 가장 큰 요소는 `.card-points`(182px, 전체의 약 36%),

  큰 `.card-points`에는 **글자 수 축소뿐 아니라 구조적 축소(불릿 개수 3개 → 2개 권장)**를 함께

이상") 기준을 모두 충족했다. 스크린샷 4장을 마스터가 직접 열어 육안으로 확인한 결과

폴더에는 이번 검증으로 인한 CSS/HTML 파일 변경이 없음을 `git status`/`git diff`로 확인했다.

## 카드뉴스 전용 line-height 기준 판단 (2026-10-29, 디자인팀)

### 배경

2026-10-28 전면 정적 대조("애매함/범위 밖으로 남긴 항목" 섹션)에서 `.card-title`의
`line-height: 1.4`(104행)와 `.card-disclaimer`의 `line-height: 1.5`(137행)가
`style-guide.md` 2번("단락 간 줄 간격 1.7~1.8배 권장")보다 낮다는 점이 발견됐지만,
"카드뉴스 전용 line-height 기준이 아직 없어 명백한 실수인지 판단하기 애매하다"며
수정하지 않고 보류됐다. 오늘은 그 판단을 직접 내린다.

### 판단 — 카드뉴스에는 본문과 별도의 line-height 기준이 필요하다

아래 근거로 "필요하다"고 판단했다.

1. **용도·텍스트 밀도가 본문과 다르다.** `style-guide.md` 2번의 1.7~1.8배 권장은 문서
   맨 위에 명시된 분석 대상(`posts/2026-09-13-interest-rate-impact.md`)의 **긴 서술형
   단락**(2~4문장, 150~250자, 여러 줄에 걸쳐 이어지는 연속 읽기)을 근거로 만들어진
   규칙이다(2번 섹션 본문 "단락 간 줄 간격" 표현도 다줄(多行) 단락을 전제한다). 반면
   카드뉴스의 `.card-title`은 2026-10-13/14 글자 수 재조정 결과 최대 2줄(제목), `.card-disclaimer`는
   최대 1줄(면책 문구, 재조정 기준 18자)로 압축된, 스캔 위주의 짧은 텍스트다(이 문서
   위 "재조정된 권장 최대 글자 수" 표 참고). 1.7~1.8배가 주는 이득(여러 줄을 눈이
   따라가며 줄을 잃지 않게 돕는 것)은 애초에 줄 수가 1~2줄뿐인 요소에는 적용될 여지가
   거의 없다.
2. **카드 공간이 극도로 타이트하다.** 2026-10-13/14 오버플로 실측에서 1:1 카드의
   콘텐츠 wrapper 예산은 **346.2px**이었고, 재조정 후 계산값은 **334.08px**(여유 약
   12px, 약 3.5%)에 불과했다(이 문서 위 "재조정 후 예상 높이 재계산" 섹션). 이 계산은
   `.card-title`을 1.4, `.card-disclaimer`를 1.5로 고정한 채 나온 결과다. 만약 둘을
   1.7~1.8로 올리면 `.card-title`은 2줄 기준으로 1줄당 약 4.1~4.6px(0.3~0.4 × 25.6px)씩,
   `.card-disclaimer`는 1줄 기준으로 약 3.2~4.8px(0.2~0.3 × 16px) 더 필요해져 이미 3.5%
   여유밖에 없는 예산을 다시 잠식한다. 어렵게 PASS를 확인한 오버플로 여유를 본문 규칙을
   그대로 복사해 오는 것만으로 다시 깎아먹을 이유가 없다.
3. **사이트 자체 CSS(`design/site.css`)도 이미 "용도별로 다른 line-height"를 쓰고
   있다.** 본문 `body`는 1.75(29행), heading `h1, h2`는 1.4(43~45행), `h3`도 1.4(73행),
   블로그 글 안의 면책 문구 `.disclaimer`는 1.7(157행, 다만 이는 흐르는 블로그 포스트
   하단에 자유롭게 배치되는 **긴 서술형 문단**이라 본문과 동일하게 1.7을 쓴 것), 코드
   블록 `pre`는 1.6(198행)이다. 즉 "모든 텍스트는 1.7~1.8"이 아니라 **heading은 1.4,
   코드 블록은 1.6, 자유 서술형 긴 문단(본문·블로그 면책 문구)은 1.7~1.75**로 요소 성격별로
   이미 구분돼 있다. 카드뉴스의 `.card-title`이 heading 역할(1.4)을, `.card-disclaimer`가
   "짧게 압축된 경고 박스"(블로그의 자유 서술형 `.disclaimer`와는 다른 성격) 역할을 하는
   것은 이 기존 구분 체계의 연장선이지, 거기서 벗어난 예외가 아니다.
4. **접근성 하한(WCAG 1.4.8)은 1.5배이며, 1.7~1.8배는 그 위에 얹은 "긴 단락 전용
   여유분"이다.** `style-guide.md` 8번은 "WCAG 1.4.8에서 권장하는 줄 간격 1.5배 이상"을
   인용하면서 "2번 항목의 1.7~1.8배 권장치는 이 기준을 상회해 안전하다"고 별도로 설명한다
   — 즉 1.5배가 접근성 기준(바닥)이고 1.7~1.8배는 본문 단락에 한해 얹은 여유 있는
   권장치다. `.card-disclaimer`의 1.5는 이 접근성 바닥을 정확히 충족하며, 1.7~1.8배라는
   "여유분"은 그 여유분이 필요한 이유(긴 단락의 연속 읽기 피로)가 성립하지 않는 카드뉴스
   짧은 텍스트에는 강제할 필요가 없다.

### 새 기준 (카드뉴스 전용, 명시)

| 요소군 | 해당 셀렉터 | 권장 line-height | 근거 |
|---|---|---|---|
| 제목(heading 역할) | `.card-title` | **1.4** | `site.css`의 heading 전용 값(`h1, h2` 1.4, `h3` 1.4)과 동일 트랙. 최대 2줄짜리 짧은 제목에는 긴 줄 간격의 이득이 적다. |
| 본문/목록/면책 등 카드 내부 짧은 텍스트 블록 | `.card-summary`, `.card-points`, `.card-disclaimer` | **1.5~1.6** (WCAG 1.4.8 하한 1.5배 이상, 1.7~1.8배까지는 올리지 않음) | 카드뉴스 텍스트는 최대 1~2줄로 압축되는 스캔형 문구이며, 오버플로 예산이 3.5%(약 12px) 여유밖에 없어 본문 단락용 여유분(1.7~1.8)을 그대로 가져오면 다시 초과 위험이 생긴다. 접근성 바닥(1.5)만 지키면 충분하다. |

이 기준은 `.card-eyebrow`(라벨, line-height 미지정 — 1줄 고정이라 영향 없음)와
`.card-footer`(1줄 고정, line-height 미지정)에는 적용 대상이 아니다(둘 다 1줄만 쓰는
요소라 line-height 값 자체가 결과에 영향을 주지 않는다).

### 현재 `card-template.html` 값 대조 — 수정 불필요

| 셀렉터 | 실제 값 (줄 번호) | 새 기준 | 일치 여부 |
|---|---|---|---|
| `.card-title` | `line-height: 1.4` (104행) | 1.4 | 일치 — **수정 안 함** |
| `.card-summary` | `line-height: 1.6` (111행) | 1.5~1.6 | 일치 — **수정 안 함** |
| `.card-points` | `line-height: 1.6` (122행) | 1.5~1.6 | 일치 — **수정 안 함** |
| `.card-disclaimer` | `line-height: 1.5` (137행) | 1.5~1.6 | 일치(하한값) — **수정 안 함** |

네 값 모두 오늘 새로 세운 카드뉴스 전용 기준을 이미 충족한다. 2026-10-28에 보류됐던
`.card-title`(1.4)·`.card-disclaimer`(1.5)는 "명백한 실수"가 아니라, 카드뉴스라는
매체(짧은 스캔형 텍스트 + 극도로 타이트한 고정 캔버스)에 맞는 값이었다는 결론이다.
따라서 **`design/card-template.html`은 이번 판단으로 수정하지 않는다.**
